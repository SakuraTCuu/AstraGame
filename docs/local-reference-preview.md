# Local Reference Preview

The user authorized temporary use of their local WeChat resource cache on 2026-09-05. Cached content, generated profiles, tables, and screenshots remain in ignored local directories. They are not part of the Git repository or the Zhushen module export.

## Run

Build the project with Cocos Creator 2.4.15, then stage the authorized cache:

```powershell
node tools/stage-reference-cache.mjs --cache '<authorized gamecaches directory>'
```

Serve `build/web-mobile`, and open `http://127.0.0.1:4174/?reference=1`. The reference mode is restricted to a localhost browser URL. The default URL continues to use the independent combat fixture. Restage after a Creator build or after visiting additional areas in the reference game.

The optional `tools/fetch-reference-map.mjs` command accepts `--cache`, `--base-url`, and `--map`. It compares the remote map configuration with the supplied cache before downloading missing PNG tiles. Downloads and their SHA256 manifest remain in ignored `reference-private/downloads`; staging includes this supplement automatically. It never changes the WeChat cache.

## Asset Pipeline

- `cacheList.json` resolves original import/native paths to cached files.
- The base and extension bundle configurations are joined by decoded UUID. Pack ordering and version indices are preserved, including textures referenced across the two parts.
- Resource-only bundles load through Cocos `assetManager`. Original game scripts are not loaded.
- Table archives use bounded length fields, the compression flag, zlib, and JSON. `__KEY_MAP__` supplies field names; `$id` references resolve within the same field.
- `profile.json` supplies the local scene and presentation bindings. `audit.json` records missing art and adaptation limits.
- Ground textures use their logical slice dimensions. Native cache images may be reduced to 819 pixels while representing 1024 logical pixels.
- Visible map tiles load on demand and release when outside the viewport. Character nodes follow the existing combat snapshots.

The skill adapter compiles source coefficients, pre/post timing, target counts, projectiles, public cooldown groups, energy costs, HP/time gates and supported buffs. Comparison heroes start at zero stars; skills with later star requirements are excluded, including otherwise hidden passive groups. Alternate-form suffixes remain audited and higher-star skill changes are not exposed as an upgrade command yet. Periodic parity still needs direct live checks: damage uses current caster attributes, all layers share an expiry/tick clock, and immediate settlement adds full ticks without consuming the status. Fractional settlement, snapshot versus current attributes, critical behavior and conditional passives remain unconfirmed or incomplete. The existing defense formula is still provisional. Supporting these periodic actions does not mean every skill of the newly deployable heroes is complete.

Unconditional permanent character traits now become the owning actor's intrinsic modifiers. They are not copied to teammates. This includes supported soul/physical/periodic bonuses, health percentage and PvE-only reduction; conditional traits and unsupported chance-based effects stay in the audit. The tank passive's redundant trailing bracket is normalized with an explicit audit entry. Soul vulnerability retains its negative reduction sign. Holy, punishment and untyped skill damage retain separate identities instead of inheriting physical modifiers; their specialized formulas remain incomplete.

Intrinsic and temporary health modifiers preserve health ratio when their cap changes. Saves normalize temporary health bonuses out of active and reserve health, since temporary statuses are not resumed, while retaining intrinsic traits. Health scaling currently uses the computed base cap, including equipment/rank contributions; that scope and rounding still need live comparison.

The live character panel shows a 2% normal-attack energy return and the attribute definitions distinguish normal-attack and tactical-skill gains. The current shared cast-energy gain and passive regeneration mapping remain provisional. Separating those gains and verifying on-hit versus on-cast timing is the next combat correction; level-10 capacity unlock alone does not establish full energy parity.

The renderer uses the scene's 549 foreground polygons and region light switches. It copies the visible ground into a render texture and composites only foreground pixels over actors. Directional regions use a smaller ambient light plus the flashlight cone.

Still incomplete: defense/critical calibration, specialized enemy actions and conditions, multiple-warning layouts, damage-limit rules, sword-fan timing, full skill effects, advanced recruitment/growth and remaining task actions, random reward groups, complete enemy art and exact overview styling. `audit.json` lists unresolved skill actions and progression conditions instead of claiming complete adaptation.
